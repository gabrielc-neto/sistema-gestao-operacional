## 12:03 — Investigação sumiço de documentação (motoristas + frota)

**Sintoma:** documentação de motoristas e veículos preenchida ontem sumiu parcialmente.

**Diagnóstico — 2 bugs no backend:**

1. `backend-vps/src/routes/collections.js` (motoristas, e toda coleção genérica)
   - POST/PATCH usavam `data || $3::jsonb` — operador JSONB `||` do Postgres é **merge RASO**.
   - Sub-objetos (documentos.cnh, endereco, contato) eram **substituídos inteiros** a cada patch, não mesclados.
   - Ex: PATCH `{documentos:{cnh:{numero:"X"}}}` apagava validade/categoria que estavam salvos.

2. `backend-vps/src/routes/veiculos.js` (frota)
   - PATCH tinha whitelist `EXTRAS_KEYS = ["documentosAplicaveis"]` — só esse campo era aceito no JSONB `extras`.
   - Qualquer outro campo custom (aet, ipem, licenca estadual, novos docs) enviado pelo frontend era **ignorado silenciosamente** (sem erro).
   - POST (upsert): se body mandasse `extras: {}` vazio, `ON CONFLICT DO UPDATE SET extras=EXCLUDED.extras` **apagava** o extras salvo.

**Correções aplicadas (código):**

- `backend-vps/schema/014-jsonb-deep-merge.sql` — nova função PG `jsonb_deep_merge(a, b)` recursiva.
- `backend-vps/src/routes/collections.js` — POST e PATCH agora usam `jsonb_deep_merge` no lugar de `||`.
- `backend-vps/src/routes/veiculos.js`:
  - Removida whitelist `EXTRAS_KEYS`; qualquer campo não-mapeado do body vira `extras` automaticamente.
  - POST e PATCH usam `jsonb_deep_merge` no `extras` — nunca mais apaga sub-objeto.
  - Set `NAO_EXTRAS` protege campos internos (id, timestamps, alias `motorista`) de virar extras.

**Arquivos:**

## 12:24 — Autorevisão pré-deploy (Wesley pediu)

Achei 1 bug real na função `jsonb_deep_merge`:
- `jsonb_object_agg` sobre conjunto vazio retorna SQL NULL em vez de `{}`.
- Impacto: se ambos os lados (atual e patch) forem `{}` num sub-objeto, o merge apagaria e viraria NULL — regressão silenciosa.
- Fix: envolvi o SELECT com `COALESCE(..., '{}'::jsonb)`.

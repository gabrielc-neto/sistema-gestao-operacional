## 17:20 — Bug crítico: docs vencidos apareciam como OK
Wesley: "como está ok se venceu o civ?" (screenshot CIV AQR-9374 venc 27/07/2026,
hoje 10/08/2026, mas status OK).

**Root cause:** função `calcStatus` (linha 200) concatenava `vencStr + "T00:00:00"`.
Coluna PG `venc` (DATE) chega no JSON como ISO datetime `"2026-07-27T00:00:00.000Z"`.
Concat gerava `"2026-07-27T00:00:00.000ZT00:00:00"` → Date inválida → `diff = NaN`.
Comparações `NaN < 0`, `NaN <= 30` = false → caía no `else statusData = "ok"`.

**Impacto:** TODOS os documentos com venc no PG viravam "OK" silenciosamente,
mesmo vencidos há meses. Só datas futuras funcionavam "por sorte" (o mesmo NaN
levava ao mesmo "ok" que seria o resultado real).

**Fix:** `String(vencStr).slice(0, 10)` — pega só a parte da data
(`"2026-07-27"`), depois concatena `+"T00:00:00"`. Funciona com ambos
formatos: `YYYY-MM-DD` (input HTML) ou ISO datetime (PG). Aplicado também
ao `agendamento`. Guard `Number.isNaN(diff)` cai em `"sem_data"` (falha
segura) se ainda vier lixo.

Deploy: 10.7s, backup `/var/pontual/backup-prod-20260810-201740.tar.gz`.

  inconsistência em salvamentos futuros (legacy_id composto diverge)

- Regra `is9eixos` restrita a rodotrem
- 3 pares de duplicados no banco pendentes
